# Languages (i18n)

Miniverse is written in English first and translated, like Minecraft: every text the player sees has a key in
`src/lang/en.json` (the base) and the same key in each translation (`src/lang/es.json`). The code never carries the
text itself, only the key.

**Where we are (2026-11-12):** the system is in place, and the static HTML (`index.html`: login, menus, pause,
controls, window titles, tooltips) goes through it, in English and Spanish. The texts written by the JavaScript are
still in Spanish in the code: they move to keys in phase F5. Until then English is only partly done, so the automatic
choice gives Spanish to everyone (see *Choosing the language*); English can be picked by hand.

## Files

| File | What it is |
| --- | --- |
| `src/i18n.js` | `t()`, `tHtml()`, `tList()`, `noun()`, `fmt`, `defineNames()`, `applyDom()`, choosing and switching the language |
| `src/lang/grammar.js` | the grammar that needs code: articles and gender in Spanish, a/an in English |
| `src/lang/en.json` | English, the base: complete, flat keys |
| `src/lang/es.json` | Spanish: the same keys, plus grammar data of nouns (`.g`) |
| `tools/i18n_check.py` | static check, without Node (see *Checking*) |
| `tools/gate.sh` | quick checks before publishing: module syntax (`jsc`), the JSON files and `i18n_check.py` |

The JSON files are loaded with top-level `await` in `src/i18n.js` (`fetch` with `?v=<miniverse-version>`, because the
cache trick of `index.html` only refetches `.js`), so every module that imports `i18n.js` already has its language
when it runs. If they cannot be loaded, the game's import fails and `index.html` shows its "try again" screen, which
carries its own three sentences in both languages. They must be in git: the world server runs the published copy,
served by `multijugador.py` (`WEB_FILES` lets `src/lang/*.json` through). A `multijugador.py` started before that
change does not serve them: then the world server, and only it, goes on without them (the keys as texts; it shows
nothing to anybody) until `multijugador.py` is restarted.

## The rule: how to add a text

1. **Never write a text the player sees in the code.** Write `t('area.thing', params)` and add the key to
   **`src/lang/en.json` and `src/lang/es.json` in the same change.** English is the base: a key missing in a language
   falls back to English, then to the key itself.
2. In the HTML, put the English text and a `data-i18n="key"` (text), `data-i18n-html="key"` (markup that comes from
   the language file: `<kbd>`, `<b>`) or `data-i18n-attr="title:key;aria-label:key;placeholder:key"`. `applyDom()`
   translates them at startup and on every switch. An element whose text the code changes gets no `data-i18n`: the
   code sets it with `t()`. An element with children (an input inside a label) gets its text in a `<span data-i18n>`,
   because `data-i18n` replaces the whole text of the element.
3. Whole sentences, never pieces glued together: `t('action.door.open')`, not `t('open') + ' ' + t('door')`. A sentence
   that changes with a number or a gender carries it inside: `plural` and `select`.
4. Numbers with `{n}` or `#` (formatted for the language: 2,5 in Spanish), lists with `fmt.list()`, dates with
   `fmt.date()`, sorting with `fmt.compare()`. Never `toLowerCase()` a translated sentence: use `{item, lower}`.
5. Player names and anything else that comes from outside, into `innerHTML`, only with `tHtml()` (it escapes the
   parameters; the message itself is ours).
6. Proper names are not translated: Miniverse, Pueblo Brotes, Nilo, Rosa, Lía… (they may go in the files with the same
   value).
7. Run `python3 tools/i18n_check.py` (or `sh tools/gate.sh`) before publishing.

## Keys

Lowercase, dot-separated, `snake_case`, like Minecraft's `en_us.json`: `gui.menu.continue`, `controls.walk`,
`item.carpenters_bench`. Built only from ids, never from a text that is shown: `t('item.' + id)` is fine.

| Prefix | For |
| --- | --- |
| `gui.*` | fixed screens and `index.html` (`gui.login.title`, `gui.pause.save_quit`, `gui.settings.language`…) |
| `controls.*`, `key.*` | the controls list (`controls.walk`; `controls.jump.keys` for the key column) and key names (`key.click`) |
| `common.*` | OK, Cancel, Yes, No, Close, Back, Done |
| `lang.*` | each language named in itself (`lang.en` = English, `lang.es` = Español) |
| `count_item` | "{n} × {item, lower}" |

Coming in F5 (the plan is in the session notes): `hud.*`, `action.*`, `use.*`, `toast.*`, `why.*`, `item.<id>` (+
`.desc`, `.g`), `piece.*`, `animal.*`, `biome.*`, `npc.*`, `commands.*`, `account.*`…

## Messages

A small subset of ICU MessageFormat, compiled once per key and cached (`t()` can run every frame):

| Syntax | Example (en / es) |
| --- | --- |
| `{name}` | `"Hello, {name}!"` / `"¡Hola, {name}!"` |
| `{n, plural, …}` with `one`, `other`, `=0`… and `#` | `"{n, plural, one {# day} other {# days}}"` / `"{n, plural, one {# día} other {# días}}"` |
| `{x, select, …}` | `"{sex, select, girl {¡Qué madrugadora!} other {¡Qué madrugador!}}"` |
| `{x, number}` | the number formatted for the language (a bare `{n}` does it too) |
| `{x, the}` / `{x, a}` / `{x, lower}` | `"Use {item, the}"` / `"Usar {item, the}"`: "Use the anvil" / "Usar el yunque" |
| `{x, al}` / `{x, del}` (Spanish only) | `"Atacar {target, al}"`: "Atacar al ciervo", "Atacar a la vaca" |
| capital first letter: `{x, The}`, `{x, A}` | at the start of a sentence: "La vaca está aquí" |

Apostrophes are plain letters ("Don't"); `''` is an apostrophe and `'{…}'` literal braces, as in ICU. A parameter
that is missing shows as `{name}`, so it gets noticed.

### Nouns, articles and gender

Pass a noun with `noun(kind, id)`: `t('use.place', { item: noun('item', 'anvil') })`. Its name is the key
`item.anvil` and its grammar comes from the same file:

```json
"item.planks": "Tablas",            "item.planks.g": "fp",
"item.stonecutters_table": "Mesa de cantero", "item.stonecutters_table.g": "f",
"item.axe": "Hacha", "item.axe.g": "f", "item.axe.the": "el hacha", "item.axe.a": "un hacha"
```

- Spanish: `.g` is `m` (the default), `f`, `mp` or `fp`. `.the` / `.a` override the article when the rule does not
  fit ("el hacha"); `al`/`del` follow `.the`.
- English: `a`/`an` from the first letter; `.an: false` or `true` for exceptions ("a unicorn", "an hour"); `.mass:
  true` or `.plural: true` for no article ("wood", "planks").
- Both: `.keepCase: true` keeps capitals inside a sentence (a proper name); `.lower` gives the exact lowercase form.

A plain object `{ name, g… }` or a string (a player's name) also works as a noun.

### Catalogs

`defineNames(ITEMS, 'item')` turns `name` and `desc` of every entry into getters that read `item.<id>` and
`item.<id>.desc`, so the hundreds of places that read `ITEMS[id].name` keep working and change language by
themselves. While a key is missing, the old value is used. (Ready, not used yet: that is F5.)

## Choosing the language

1. `?lang=en`, `?lang=es` or `?lang=keys` in the URL (for tests; `keys` shows the keys instead of the texts).
2. The saved setting: `lang` in `pueblo-brotes:ajustes` (`'auto'`, `'en'` or `'es'`). Settings has a **Language ·
   Idioma** section (Automatic, English, Español) and the login screen and the main menu an **EN | ES** picker; both
   switch without reloading (reloading would ask for the password again).
3. On automatic, the language of the account that logs in (`save.lang`, see below).
4. Automatic: the browser's language (`es*` gives Spanish, anything else English), **but only among `AUTO_LANGS`** in
   `src/i18n.js`, the languages the whole game is translated into. Today that is `['es']`, so automatic gives Spanish
   to everyone. **When F5 is done, add `'en'`** (and the same list in the early script of `index.html`; the check
   tool compares them): from then on automatic follows the browser, with no other change.

The world server (`?modo=servidor`) and the automatic tests (`?modo=pruebas`) stay in Spanish (or `?lang=`), and
neither decides nor saves the setting.

**Games that already existed stay in Spanish:**

- The first time this version runs in a browser, if it already has data of the game (any `pueblo-brotes:*` key in
  localStorage, or the `pueblo-brotes` IndexedDB), the setting is saved as `'es'`; in a new browser, as `'auto'`. It is
  decided once (the field is then present). Old versions just carry the extra field along.
- An account whose save has no `lang` (made before this version) stays in Spanish when it logs in on a browser that is
  on automatic. Every save now carries `lang`: the explicit choice of the device that saved it, or on automatic the
  account's own (so an old account keeps saying Spanish), or `'auto'`.

## Switching while playing

`setLang(l)` loads the file if needed, re-translates the static HTML with `applyDom()` and fires `langchange` on
`window` (`onLangChange(fn)`). The screens with texts from `t()` listen and redraw (today: Settings and the EN | ES
picker). What is already in the chat or in a notice stays in the old language, as in Minecraft. `<html lang>` follows.

## Checking

- `python3 tools/i18n_check.py`: same keys in every language, same parameters and markup, well-formed messages
  (`plural`/`select` with `other`), formatters that exist in each language, every `t('literal')` and `data-i18n*` of
  `src/` and `index.html` present in `en.json`, and the automatic list of `index.html` equal to `AUTO_LANGS`.
- `--strict`: also counts the Spanish texts left in the code. It fails until F5 is done; that is expected.
- `--unused`: keys no literal uses (some are built from ids: only a hint).
- In the browser: `?i18n=check` warns once in the console for each key shown without a translation; `?lang=keys`
  shows the keys, so what is not a key yet stands out.
- Test: `index.html?modo=pruebas&only=idioma` (in `src/pruebas.js`).

## Adding a language

1. Copy `src/lang/en.json` to `src/lang/<code>.json` and translate the values (keep the keys and the `{parameters}`).
2. Add it to `LANGS` in `src/i18n.js`, named in itself (`fr: 'Français'`), and its key `lang.<code>` to every file.
3. If its grammar needs code (articles, gender, contractions), add it to `GRAMMAR` in `src/lang/grammar.js` and its
   formatters to `FORMATTERS` in `tools/i18n_check.py`.
4. When it is complete, add it to `AUTO_LANGS` (and the list in `index.html`).
5. `python3 tools/i18n_check.py`.
